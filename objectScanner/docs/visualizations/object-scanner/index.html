STEP 01 · PREPARE

Calibrate the object

Four temporary setup tags define a metric box. A fixed permanent-tag map recovers that box across camera views after setup-tag removal. Its center, axes and eight corner identities define the common frame for labels and measured points.

PROCESS IN MOTION01 / 06
00.0 / 12s

ILLUSTRATIVE SEQUENCE · NOT LIVE TELEMETRY

INPUT

Object, setup tags and permanent table tags

OUTPUT

Calibration, metric box dimensions and fixed object frame

How it works

  1. Detect two tag populations

    Estimate each tag pose from its known square size and image corners. The collection wrapper uses tagStandard41h12, setup IDs 1–4 at 14 mm and permanent IDs 5–10 at 28 mm. Wrong physical sizes directly corrupt metric scale.

  2. Resolve the setup roles

    Find the raised tag using height above the table. Of the remaining three, choose the origin whose two neighbor vectors are closest to perpendicular. Swap X and Y when needed so their cross product points toward the raised tag; numeric IDs do not prescribe placement roles.

  3. Construct a rigid box

    Normalize the first base edge, remove its component from the second edge, and form Z by their cross product. Edge lengths and top height define dimensions. Place the object origin half a width, length and height from the resolved base origin.

  4. Freeze the table relationship

    Use the first visible permanent tag as the table frame. Store all visible permanent-tag transforms and T_table_object. A later camera view solves the mapped board pose and composes it with this fixed object transform.

  5. Persist the contract

    Save calibration.json with dimensions, revision, tag sizes, resolved roles and box_center. Additional permanent tags can be mapped while two existing tags remain visible. Reconfiguring the box changes its revision and relabels existing captures through the preserved table frame.

THE CORE RELATIONSHIP

One frame across views

T_camera_object = T_camera_table × T_table_object

The first transform changes with camera viewpoint; the second is fixed by calibration. Object points map to camera coordinates as P_camera = T_camera_object × P_object, with translations in metres.

Checks before moving on

  • Confirm the printed tag family, black-square physical size and the configured sizes agree.
  • Keep permanent tags and the object fixed relative to one another throughout collection.
  • Inspect the projected box from several views before accepting the calibration; pixel reprojection alone cannot prove the desired object boundary.

STEP 02 · PREPARE

Capture RGB-D views

Each manual capture saves raw RGB, a tag-inpainted training image, aligned depth and a geometric label. Mapped tags determine its pose. The operator chooses useful viewpoints; the script does not measure coverage or automatically reject blur.

INPUT

Calibrated object and RGB-D camera

OUTPUT

Color, aligned depth, intrinsics and T_camera_object per view

How it works

  1. Read one calibrated RGB-D observation

    Request color and depth from the chosen backend using collection depth limits. Save current intrinsics and image dimensions so projection and depth backprojection share camera geometry.

  2. Recover the current box pose

    Detect permanent tags and solve their combined board pose from the fixed map. At least two mapped tags must be visible, and their board reprojection error must pass. Compose T_camera_object and project the canonical box center and eight corners.

  3. Gate the manual capture

    Space or the Capture button requests a save. The request is refused if no valid label exists, any temporary setup tag is still detected, or a timestamp filename already exists. A partly clipped box is recorded with a flag; an entirely invalid clipped box cannot produce a label.

  4. Save raw and model images

    Keep raw_images for audit. Inpaint permanent tag regions into images for learning, reducing a visible fiducial shortcut. Save depth without annotation graphics; zero means invalid and each integer unit is 0.001 m.

  5. Write geometry and indexing

    The JSON carries timestamp, camera_color_optical_frame, box_center, calibration revision, metric pose, intrinsics and projected corners. Export the corresponding CenterPose sample, then append image/depth/label paths to samples.jsonl. An export failure is reported after the raw audit files have been saved.

STEP 03 · PREPARE

Review foreground masks

BiRefNet proposes foreground; geometry and image heuristics isolate the rigid object. The resulting mask supports segmentation, background replacement and fusion. Previews support human review, but numerical warning gates do not record human approval.

INPUT

Captured color images and calibrated pose labels

OUTPUT

Reviewed object masks paired with captured views

How it works

  1. Infer with object context

    Read the inpainted RGB image and its pose label. Expand the projected box bounding rectangle by 60% of its larger dimension, clip to the image and run the local pretrained BiRefNet at 1024 × 1024. Restore probabilities to original image coordinates.

  2. Try a bounded threshold ladder

    Threshold foreground probabilities at 0.5, then lower in 0.1 steps toward 0.2 if refinement fails to produce a usable component. If crop inference cannot produce a result, retry full-frame inference. Lower thresholds recover weak foreground; they do not establish mask correctness.

  3. Constrain and disconnect

    Restrict candidates to the projected 2D bounding rectangle plus 3% padding, with a two-pixel minimum. Subtract changed regions detected between raw and inpainted images. A bright-neutral HSV heuristic also breaks connections through pale paper and surfaces.

  4. Choose the object component

    Apply an 11-pixel elliptical morphological opening to break thin connections such as cables. Prefer the connected component containing the projected object center; otherwise use the largest. Fill its largest external contour, then subtract the inpaint exclusion again so excluded tag pixels are not filled back in.

  5. Review evidence before export

    Write raw_masks, refined masks, previews and contact sheets. Inspect silhouettes, concavities and thin structures. Warnings abort the staged build by default; --allow-warnings permits them and requires closer review.

This is only the initial binary mask. Spatial constraints, exclusion, opening and component selection further modify it. A probability above threshold is a model score, not a calibrated accuracy guarantee.

STEP 04 · PREPARE

Export paired labels

Segmentation receives a reviewed silhouette contour; pose receives eight canonical projected box corners. Both use the same images, masks and split membership. These labels describe visible foreground and a virtual 3D box, respectively.

INPUT

Reviewed masks, source images and projected box corners

OUTPUT

Paired YOLO segmentation and eight-keypoint datasets

How it works

  1. Plan source-grouped splits

    Use an existing split manifest when available. Otherwise select 12.5% of source views for validation with seed 317. Materialized variants of a held-out source stay out of training; default export uses original images only.

  2. Convert the reviewed silhouette

    Find external contours, discard small components and simplify with a perimeter-relative tolerance. Require exactly one surviving object polygon. Rasterize it back to a mask and reject excessive disagreement, exposing lost holes or disconnected regions instead of silently accepting a poor representation.

  3. Verify the corner contract

    Read all eight finite corner projections in immutable XYZ sign order. When intrinsics and T_camera_object are available, recompute the canonical box projection and require agreement within 0.0001 px. All samples must use the same box dimensions.

  4. Normalize without inventing observations

    Normalize polygon coordinates, the mask-derived object bounding box and in-image keypoints by image dimensions. Encode an off-image corner as (0, 0, 0); do not clamp it to a border. In-image visibility 2 means its projection exists, including a physically occluded virtual corner.

  5. Preserve pairing into training

    Write matching task images, labels, masks, combined annotations and YAML files with kpt_shape [8, 3]. Background compositing later replaces only pixels outside the mask, preserving foreground positions. Disable whole-image horizontal flips because mirroring does not preserve the corner identity contract.

STEP 05 · PREPARE

Fuse the metric reference

The reference is a sibling branch independent of YOLO training. TSDF fusion combines masked depth in box_center using saved camera poses, then crops and filters the surface into a metric cloud for runtime registration.

INPUT

Reviewed masks, captured depth and calibrated view poses

OUTPUT

reference.ply and frame metadata in box_center

How it works

What the volume actually stores

TSDF expands to truncated signed distance function. A voxel stores a bounded signed-distance estimate around an observed surface. Integrating another calibrated depth view updates that estimate by weighted averaging, so many views contribute to one surface. Voxel size controls spatial sampling; truncation controls the distance band. Neither is an accuracy measurement.

Open3D 0.19 RGB-D integration ↗
  1. Validate paired source evidence

    Require matching capture, depth, mask and label inputs, current box dimensions and calibration revision. Each saved pose must be a finite rigid transform; depth must be aligned to rectified color. By default require at least eight usable views.

  2. Reject non-object depth

    Backproject nonzero masked depth with the saved intrinsics and metric scale. Transform points into box_center and retain those inside the box with a per-axis tolerance max(3 mm, 8% of that dimension). Each view must retain at least 100 depth pixels.

  3. Integrate in the object frame

    Build a scalable TSDF volume with metric voxel and truncation lengths. Pass T_camera_object directly as its world-to-camera extrinsic because the TSDF world is box_center. Inverting that matrix here would use the wrong transform convention.

  4. Extract and clean the surface

    Extract a point cloud, crop every axis to calibrated half-dimensions plus 3 mm, and remove statistical outliers with 20 neighbors and a 2.0 standard-deviation ratio. Estimate normals within 10 mm and orient them outward relative to the box origin.

  5. Package the frame evidence

    Save reference.ply, frame.json, canonical object_keypoints.yaml and a ZIP bundle. Metadata declares metres, box_center, identity scan/object transforms and capture provenance. Optional crop editing must preserve this frame; an unrelated moving-camera diagnostic scan is a separate artifact.

STEP 06 · PREPARE

Freeze geometry + train

The wrappers verify frame consistency and freeze PnP geometry before training two models. Segmentation learns foreground selection. Pose learns the eight image-space corner identities used for initialization and recovery. Their separate checkpoints share one metric corner contract.

INPUT

Paired datasets, fixed geometry and training backgrounds

OUTPUT

Segmentation checkpoint, pose checkpoint and frozen PnP geometry

How it works

  1. Freeze geometry before optimization

    Copy calibration.json and the exported canonical object_keypoints.yaml into training_pnp, recording SHA-256 hashes and calibration revision. If a snapshot already exists, verify it and refuse a different source box. This pins two geometry files; it is not a complete training-data or checkpoint hash manifest.

  2. Check paired supervision

    Require matching image, label and mask stems in train and val for both tasks, with equal split counts. This prevents training from incomplete paired exports.

  3. Train segmentation separately

    The segmentation wrapper starts from the local emergency_stop_frozen_backbone checkpoint. Its current defaults use AdamW, 100 epochs maximum, patience 25, batch 8, image size 640, learning rate 0.0001 and freeze 11. The output run name ends _onthefly_seg.

  4. Fine-tune the corner model

    The pose wrapper overrides the generic trainer defaults: start from my_object_rgbd_unfrozen_pose/weights/best.pt, freeze 0 and learning rate 0.00005, with 100 epochs maximum and patience 25. It writes a separate _pose_refined_pose run; the generic CLI fallback yolo11n-pose.pt is not this wrapper’s initialization.

  5. Diversify backgrounds and assemble artifacts

    Both wrappers draw each source 12 times per epoch and replace its background with probability 0.85 before downstream training transforms. Only the background canvas may flip; foreground geometry stays fixed in this compositor. Validation keeps original photographs. Runtime combines both best.pt files with the frozen corners and the independently fused reference.

STEP 01 · ESTIMATE

Acquire aligned RGB-D

Make color pixels, depth samples and intrinsics describe the same rectified camera before any learning or geometry uses them.

INPUT

Live scene and camera calibration

OUTPUT

Color, aligned depth and CameraInfo

How it works

  1. Configure a real acquisition mode

    The Orbbec backend requires the advertised Close Range Default mode before enumerating profiles, then verifies disparity search range 256 and offset zero. Unsupported mode or property readback fails startup. The configured 40 mm depth cutoff is an input policy and supported range setting; it is not a measured accuracy guarantee.

  2. Align and rectify together

    Software depth-to-color alignment targets zero distortion. The SDK retains raw color, so OpenCV rectifies color separately when its coefficients are nonzero. Checks require matching dimensions and intrinsic matrices, zero aligned-depth distortion and identity depth-to-color extrinsics. Merely resizing two images would not establish this correspondence.

  3. Preserve units and pixel geometry

    SDK depth scale converts raw counts to metric depth; the worker publishes uint16 millimetres with zero for invalid depth. Color is RGB8. Downscaling adjusts focal lengths and the pixel-center convention for principal points as well as image dimensions. The default downscale of one retains the selected profile.

  4. Separate capture from publication

    An isolated SDK worker sends complete RGB-D packets to the ROS bridge. A latest-packet slot replaces superseded frames instead of building a backlog. The camera prefers 30 FPS acquisition; the launch default caps publication at 20 Hz and camera_rate can override it. Neither number promises pose throughput.

  5. Stamp and supervise each packet

    Device timestamps bound color/depth skew to half a frame period. A host timestamp becomes the common ROS stamp for color, depth and CameraInfo. The bridge drops packets outside its age window and stops a failed or timed-out worker. A common stamp enables downstream exact synchronization; it does not prove simultaneous exposures.

STEP 02 · ESTIMATE

Find the object

Use two task-specific networks, then associate their detections spatially so a mask and ordered corners refer to the selected object.

INPUT

Color frame and the two trained checkpoints

OUTPUT

Selected foreground mask and corners when initialization is needed

How it works

  1. Segment the target class

    The segmentation adapter validates checkpoint task and target class, converts the incoming RGB array to the BGR convention expected by Ultralytics, and requests original-resolution retina masks. Mask probabilities become a binary foreground region. Detection confidence and per-pixel mask threshold are separate decisions.

  2. Select an instance conservatively

    Without a remembered box, acquire the highest-confidence segmentation detection. Once acquired, select the candidate with maximum box intersection-over-union against the previous box, requiring the association threshold. A miss emits no selected mask; five consecutive misses clear this spatial association. It is not persistent identity across look-alike objects.

  3. Run corners only when needed

    The observation node listens to tracking state. With the current pose_only_for_reinitialization preset, it runs the separate pose model only outside TRACKING and only when segmentation selected an instance. During established tracking it still segments but publishes an eight-entry invalid corner placeholder for synchronization.

  4. Join the two predictions

    Pose detections are matched to the selected segmentation box by maximum box IoU, with a minimum of 0.10. The adapter preserves the trained eight-corner order and records u, v, confidence and validity. It marks nonfinite or all-zero coordinates invalid; the later PnP stage additionally applies its own corner-confidence threshold.

  5. Publish coherent observations

    Mask and keypoint messages retain the source color stamp. No segmentation produces an all-zero mask; missing pose produces invalid corners. An expired inference result resets association and returns without publishing it. The CUDA collection launcher overrides the YAML CPU device with cuda:0, keeping FP32; this does not move Phase 4 GICP onto CUDA.

STEP 03 · ESTIMATE

Extract observed geometry

Turn only the selected object’s valid depth pixels into a metric cloud, then reduce density and isolated noise before registration.

INPUT

Synchronized mask, aligned depth and camera intrinsics

OUTPUT

Filtered observed object cloud in metres

How it works

  1. Synchronize four inputs exactly

    Mask, aligned depth, CameraInfo and color must share a timestamp under the default zero-slop synchronizer. The node rejects out-of-order or over-age inputs. Matching image sizes, one optical frame, zero distortion and suitable rectification metadata are checked before using the pinhole equations.

  2. Select valid foreground depth

    Accept pixels where the mask is nonzero, depth is finite and distance lies inclusively within the configured near/far interval. The geometry function converts uint16 millimetres to metres; it also supports externally supplied float32 metre depth. A zero mask therefore produces no points instead of an unmasked scene cloud.

  3. Backproject through calibration

    For every retained pixel, divide its principal-point offset by focal length and multiply by measured Z. The result is camera optical XYZ, not the object frame. Color is sampled at those same pixels, maintaining point/color correspondence. A different configured cloud frame requires an actual timestamped TF transform rather than relabeling coordinates.

  4. Average within metric voxels

    Assign XYZ to floor-based 3 mm voxel keys. Replace each occupied cell by its mean point and average its RGB values. This reduces redundant samples in dense regions and controls registration cost. The grid belongs to the observed cloud frame; it is not a learned representation or a guarantee of 3 mm accuracy.

  5. Remove isolated samples and enforce size

    Compute each point’s mean distance to up to 20 other neighbors. Retain points below the global mean plus two standard deviations. Fewer than 30 remaining points results in a published empty cloud with insufficient_object_points status. A processing exception also publishes an empty cloud; an expired result is dropped instead.

STEP 04 · ESTIMATE

Choose the pose seed

Choose a learned geometric initializer at startup/recovery, or reuse the previous accepted raw registration pose during established tracking.

INPUT

Ordered corners + frozen geometry, or accepted raw pose history

OUTPUT

Initial T_camera_object for local registration

How it works

  1. Choose the branch from state

    INITIALIZATION or LOST requires PnP; TRACKING with a stored pose copies that previous accepted raw GICP transform. The smoothed display pose is never the tracking seed. The node first requires a sufficiently populated observed cloud, so PnP is not attempted without usable depth input.

  2. Match semantic corner identities

    Frozen object_keypoints.yaml supplies ordered metric 3D corners in box_center. The detector supplies corresponding image coordinates. Reject nonfinite, invalid or low-confidence entries and require at least four. Known metric box size resolves monocular scale; permuting corner IDs changes the physical problem even if the image points appear plausible.

  3. Find and refine a consensus

    EPNP inside RANSAC proposes object-to-camera transforms while rejecting corner outliers. It requires at least four consensus inliers, then uses iterative solvePnP only on those inliers with the consensus as its initial guess. Validate a finite transform with positive object-origin Z and mean inlier reprojection error no greater than five pixels.

  4. Validate against observed depth

    Compare the PnP translation vector with the componentwise median XYZ of the observed cloud. The gate uses full Euclidean distance, not just Z, and allows at most 120 mm. This is a bounded consistency heuristic: a visible-surface median is not necessarily the physical center of the object.

  5. Optionally correct only the seed depth

    Publish accepted raw PnP for diagnostics first. If enabled and the absolute difference between median cloud Z and PnP Z lies inclusively between 20 and 80 mm, replace seed Z with that median. X, Y and rotation stay unchanged. This correction does not modify published raw PnP and happens only after PnP passes its checks.

STEP 05 · ESTIMATE

Refine against the reference

Use local surface registration to refine a good seed, then require multiple independent geometric quality checks before accepting its pose.

INPUT

Pose seed, fixed box_center reference and observed cloud

OUTPUT

A refined pose candidate with quality checks

How it works

What makes GICP different

Generalized Iterative Closest Point models local surface direction through a covariance for each point. For each matched pair, Open3D combines the source and target covariances, weights the position residual and its Jacobian, and solves a small rigid-motion update. This treats mismatch across a surface differently from mismatch along it. The reported acceptance metrics below are separate from that covariance-weighted optimization.

Open3D 0.19 GICP implementation ↗
  1. Keep reference and target roles fixed

    The immutable reference is the source in box_center; the observed cloud is the target in camera coordinates. Open3D receives the absolute initializer and returns the same object-to-camera transform convention. Reject invalid rigid seeds and insufficient or degenerate observed geometry before fitting.

  2. Approximate visible reference surfaces

    Transform reference points by the seed and retain positive-depth points inside the camera field of view. When stored normals exist and normal-facing is enabled, retain normals facing the camera. This removes clearly irrelevant back-facing geometry, but does not solve self-occlusion with a depth buffer.

  3. Run the enabled registration levels

    The implementation supports coarse, medium and fine levels, each with independent sampling, correspondence distance and iteration budget. Current YAML disables coarse and medium and enables fine only: 2 mm voxels, 8 mm correspondence distance and one iteration. This is conservative local refinement; the code’s converged flag means enabled levels returned valid results, not proof of full optimizer convergence.

  4. Measure fit and target coverage

    Require at least 30 correspondences, source fitness at least 0.20, inlier RMSE no more than 12 mm and overlap at least 0.10. Fitness is matched-source fraction; overlap counts unique matched observed target indices divided by target count. Many reference points landing on one small target patch cannot inflate the unique-target coverage metric.

  5. Apply initializer and motion guards

    After PnP initialization only, project the GICP result and require mean disagreement with PnP’s original inlier detections no greater than 10 px. During tracking, compare the candidate with the stored raw pose and reject translation over 120 mm or rotation over 0.8 rad. The Phase 4 GICP backend is Open3D CPU; the CUDA launch accelerates YOLO, not this solver.

STEP 06 · ESTIMATE

Accept, smooth + publish

Commit validated raw poses to tracking state, smooth only accepted results, and publish an overlay that reflects acceptance for the current observation.

INPUT

Validated GICP candidate and tracking state

OUTPUT

Filtered object pose, box_center TF and camera box overlay

How it works

  1. Commit only after every gate

    The node checks freshness again after PnP and GICP. A valid final candidate passes geometric, initialization-consistency and temporal-motion gates before state.accept stores the raw transform, clears failures and enters TRACKING. The filter then receives that accepted raw candidate. Rejected fits never replace the seed or contaminate smoothing.

  2. Smooth translation and rotation appropriately

    The first accepted pose after a reset initializes the filter unchanged. Later translations use an exponential weighted average with alpha 0.45. Rotations use spherical interpolation between prior filtered orientation and new accepted orientation at fraction 0.45; averaging rotation-matrix elements would generally destroy rigid rotation geometry.

  3. Recover after counted failures

    A reject call increments the state failure counter. One failure preserves the prior raw seed while TRACKING; the second consecutive failure sets LOST and clears it. The node resets the filter whenever state needs PnP. The observation node learns that state through ROS and resumes corner inference for recovery.

  4. Distinguish rejection from silence

    Stale or out-of-order inputs, expired PnP results and expired GICP results return without calling reject. They therefore do not increment failures or reset tracking. There is no pose-node watchdog that automatically changes TRACKING to LOST solely because synchronized observations stop arriving. Consumers must check timestamps rather than infer freshness from state alone.

  5. Publish raw diagnostics and filtered output

    Accepted results publish raw GICP, filtered pose, compatibility /object/pose and the box_center TF. Optional debug TF and reference clouds aid inspection. The box overlay projects filtered corners only when their camera depths are positive; rejection publishes a current image without an accepted box. Base-frame pose is conditional on an available timestamped base-to-camera TF and does not block camera-frame acceptance.
